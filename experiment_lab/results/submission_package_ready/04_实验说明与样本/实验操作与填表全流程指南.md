# 云端事故复盘实验：操作与填表全流程指南

本文与《云端事故复盘能力实验说明文档.md》、预填表《云端事故复盘实验数据记录表（预填版）.md》配套，按**真实工程路径**写死命令与文件名习惯。

---

## 一、开始前准备

### 1.1 电脑端后端

1. 进入目录：`VehTrust0518/backend/`  
2. 新建或编辑 `.env`（勿提交到 Git）：
   - `OPENAI_API_KEY=`（必填）
   - `OPENAI_MODEL=`（可选，如 `gpt-4o-mini`）
   - `OPENAI_BASE_URL=`（可选，兼容 OpenAI 协议的网关）
3. 安装依赖并启动（PowerShell 示例）：

```powershell
cd D:\Users\Desktop\VehTrust0518(1)\VehTrust0518\backend
pip install -r requirements.txt
uvicorn main:app --host 0.0.0.0 --port 8080
```

保持该窗口**一直运行**，直到所有批量跑完。

### 1.2 Android 端

1. 用 Android Studio 打开工程 `VehTrust0518`，编译安装到**模拟器**（默认后端地址一般为 **`10.0.2.2:8080`**，即访问你本机 8080 端口）。  
2. 若用**真机**：把 App 里访问后端的地址改成你电脑的**局域网 IP**（如 `192.168.1.x:8080`），并保证手机与电脑同一 WiFi。

### 1.3 确认样本

- 批量实验读取：`app/src/main/assets/experiment_samples_realistic_50.json`（**50 条**）。  
- 若你在 `backend/` 里重新生成了样本，务必**再复制一份**到上述 `assets/` 路径，与 App 保持一致。

## 二、主实验：A / B / C（消融一律用 D0）

目标：每个样本在 **三种方法** 下各生成一次云端结果，得到 **3 个 JSON 文件**（各含 50 条包装结果）。

| 次序 | **列表页**「云端实验」设置 | 列表页操作 | 得到文件（示例名） |
| ---- | -------------------------- | ---------- | ------------------ |
| 1 | 分组 **A**，消融 **D0** | 点 **「批量跑 50 条并保存结果」** | `cloud_experiment_results_A_D0_yyyyMMdd_HHmmss.json` |
| 2 | 分组 **B**，消融 **D0** | 同上 | `cloud_experiment_results_B_D0_....json` |
| 3 | 分组 **C**，消融 **D0** | 同上 | `cloud_experiment_results_C_D0_....json` |

### 2.1 操作细步

1. 打开 App → **事故溯源**（**列表页**，不要进入某条详情也可完成全部实验）。  
2. 在列表页上方 **「云端实验（列表统一设置）」** 区域选择 **A / B / C** 与 **D0～D4**（主实验三组均用 **D0**）。选择会**自动保存**，下次打开 App 仍保留。  
3. 点 **「批量跑 50 条并保存结果」**，等待结束。  
4. 成功后在列表下方状态区可见保存路径；文件在：  
   `Android/data/<包名>/files/cloud_experiment_results_A_D0_*.json`  
5. **（推荐）** 多次跑完后，点 **「汇总拷贝到归档文件夹」**：会把当前目录下所有 `cloud_experiment_results_*.json` **复制**到同一子目录  
   `.../files/experiment_exports/export_yyyyMMdd_HHmmss/`  
   便于用 Device File Explorer **整夹拷贝到电脑**。  
6. 或点 **「保存全部到…」**，在系统文件选择器里选一个文件夹（如 U 盘、Download），将全部批量 JSON 写入该处。  
7. 若仍用 Device File Explorer 手动拷单文件，建议命名如 `主实验_A_D0_20260519.json`。

对 **B、C** 重复步骤 2～4（每次只改分组，消融仍为 D0）。

## 三、消融实验：固定 C 组，换 D1～D4

目标：在 **同一批 50 条样本** 上，看「去掉责任 / 环境 / 决策链 / 弱提示」对 C 组的影响；每个消融条件 **1 个 JSON**。

| **列表页**「云端实验」设置 | 列表页 | 得到文件（示例） |
| -------------------------- | ------ | ---------------- |
| **C + D0** | 批量 50 条 | 若主实验已跑过 C+D0，可直接用该文件作消融基线 |
| **C + D1** | 批量 50 条 | `cloud_experiment_results_C_D1_....json` |
| **C + D2** | 同上 | `..._C_D2_....json` |
| **C + D3** | 同上 | `..._C_D3_....json` |
| **C + D4** | 同上 | `..._C_D4_....json` |

将每个文件同样拷到电脑并命名归档。

## 四、保存与归档建议

在电脑上建文件夹，例如：

```text
实验归档/
  01_样本/
    experiment_samples_realistic_50.json   （从仓库拷一份备档）
  02_主实验原始JSON/
    A_D0_xxx.json
    B_D0_xxx.json
    C_D0_xxx.json
  03_消融原始JSON/
    C_D0_xxx.json  （可与主实验复用）
    C_D1_xxx.json
    ...
  04_CSV与统计/
    （见下一节）
```

**注意**：批量 JSON 里是模型**原始输出**，用于计分与答辩；**不要**为分数好看而手改 JSON 再统计（说明文档 §11）。

## 五、拉表：把 JSON 变成可编辑表格

在 **电脑** 上进入 `backend`（与 `export_batch_results_to_csv.py` 同级），对每个保存好的批量结果执行一次：

```powershell
cd D:\Users\Desktop\VehTrust0518(1)\VehTrust0518\backend

python export_batch_results_to_csv.py `
  "D:\实验归档\02_主实验原始JSON\A_D0_xxx.json" `
  "D:\实验归档\04_CSV与统计\主实验_A_D0.csv"

python export_batch_results_to_csv.py `
  "...\B_D0_xxx.json" `
  "...\主实验_B_D0.csv"

python export_batch_results_to_csv.py `
  "...\C_D0_xxx.json" `
  "...\主实验_C_D0.csv"
```

用 **Excel / WPS** 打开 CSV：已有列包括 `summary`、`rootCause`、`evidencePoints` 等；右侧预留了 **`Re_人工填`、`责任一致_人工填`、`N_wrong_人工填`、`N_claim_人工填`、`可读性_人工填`**，在这些列里填数或文字即可。

## 六、指标怎么算（填表时用）

以下与说明文档 **§7** 一致；金标准以预填表 **§七**（或 `experiment_samples_realistic_50.json` 里 `responsibility.reasons` + 你最终认定的主责任）为准。

### 6.1 单条样本、单种方法：关键证据召回率 \(R_e\)

- \(N_{\mathrm{gold}}\)：该样本金标准里**关键证据点条数**（当前生成样本一般为 **6**）。  
- \(N_{\mathrm{hit}}\)：模型输出（摘要 + 根因 + 证据点列表等）中，**被你认为正确命中**的金标准证据条数（需逐条对照，不能全靠关键词）。  
- **\(R_e = N_{\mathrm{hit}} / N_{\mathrm{gold}}\)**。  
- 填预填表 **§九** 中对应「样本 + 方法」那一行的 **\(R_e\)**（可填小数如 `0.67`）。

### 6.2 责任是否一致

- 看模型归纳的**主要责任因素**是否与金标准 **§七「主要责任因素」**（或你修订后的定稿）一致。  
- 表格填 **是** / **否**。

### 6.3 事实错误 \(N_{\mathrm{wrong}}\)、\(N_{\mathrm{claim}}\)、\(E_f\)

- 团队需事先约定：怎样算一条「可核查事实陈述」\(N_{\mathrm{claim}}\)（例如按句号拆句，且去掉纯评价句）。  
- \(N_{\mathrm{wrong}}\)：上述陈述里，与**输入 JSON 明显矛盾**的条数。  
- **\(E_f = N_{\mathrm{wrong}} / N_{\mathrm{claim}}\)**；若 \(N_{\mathrm{claim}}=0\)，\(E_f\) 填 **—** 并备注。

### 6.4 可读性

- 建议 **1～5 分**（或按说明文档 §7.4 四维再平均）；单人自评须在 **预填表 §〇** 写明。

### 6.5 主实验汇总（预填表 §十）

- **平均 \(R_e\)**：该组 50 个 \(R_e\) 的算术平均。  
- **\(A_r\)**：责任填「是」的样本数 **÷ 50**。  
- **平均 \(E_f\)**、**平均可读性**：对 50 条分别算再平均（\(E_f\) 为「—」的样本先约定是否剔除）。

### 6.6 消融汇总（预填表 §十一）

- 对每个消融 JSON 同样导出 CSV、同样填 \(R_e\) 等，再与 **C+D0** 对比填「平均」行。

## 九、盲评与合规（简记）

- **盲评**：理想情况是把 A/B/C 输出打乱、隐去标签再请人打分；一人做时建议「隔日打乱顺序自评」，并在 §〇 写明局限（说明文档 §6 步骤 4～5、§11）。  
- **合规**：模型输出仅作工程与教学分析，**不作司法定责结论**（说明文档 §11、预填表 §十三）。

## 十、常见问题

1. **批量失败多**：检查后端日志、`OPENAI_API_KEY`、网络；适当延长 App 侧请求超时（与后端连通性有关）。  
2. **找不到 JSON**：认准包名路径 `Android/data/.../files/`；或用 Android Studio **Device File Explorer** 搜索 `cloud_experiment_results`。  
3. **CSV 乱码**：脚本已使用 `utf-8-sig`，用 Excel 正常「自文本/CSV」导入即可。  
4. **改了样本**：先 `python generate_experiment_samples.py`，再复制到 `assets/`，再在 `experiment_lab` 下运行 `python _gen_data_record_template.py` 刷新预填表 §六、§七。
