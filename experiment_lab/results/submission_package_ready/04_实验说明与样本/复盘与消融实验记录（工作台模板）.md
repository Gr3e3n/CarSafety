## 一、事故类型体系（与 `AccidentModels.kt` 枚举一致）

说明文档 **§4.2** 六类为复盘实验核心维度；本工程另有 **碰撞**、**智驾故障** 两类，与区块链溯源中的「已发生碰撞事件」「功能安全/接管类事件」更一致，一并纳入 **50 条** 分布。

| `eventType`（JSON） | 中文含义 | 本评估集条数（50） |
| ------------------- | -------- | ------------------ |
| `COLLISION` | 碰撞/接触类（含追尾、刮擦等） | 7 |
| `AUTOPILOT_FAULT` | 自动驾驶功能异常/降级 | 6 |
| `DRIVER_SLOW_REACTION` | 驾驶员反应不足 | 6 |
| `AEB_DELAY_OR_MISS` | AEB 触发延迟或未触发 | 6 |
| `TTC_LOW_RISK` | TTC 过低导致碰撞风险 | 6 |
| `DRIVER_TAKEOVER_FAIL` | 驾驶员接管不足 | 6 |
| `ENVIRONMENT_DISTURB` | 环境因素干扰 | 6 |
| `MULTI_FACTOR` | 多因素共同作用 | 7 |

**样本与编号**：`S01` = JSON 数组第 **1** 条，`S50` = 第 **50** 条；`eventId`、`scenarioName` 以文件内为准。每条含 `responsibility.reasons`（默认 **6** 条）可作金标准证据条目；`summary`+`conclusion` 可作标准复盘参考（提交前建议人工润色）。

**派生信号**：样本含 `derivedSignals`（反应时间、制动上升时间、AEB 延迟、TTC、接管摘要等），与说明文档 **§4.3** 对齐，便于与模型输出交叉核对。

## 二、实验环境与模式切换（工程行为）

| 模式 | 含义 | 操作位置 |
| ---- | ---- | -------- |
| **A** | 模板生成（固定规则拼接） | 溯源详情页「实验分组」 |
| **B** | 通用大模型（弱结构化） | 同上 |
| **C** | 本项目结构化复盘 | 同上 |
| **D0** | 完整输入（消融基线） | 「消融」单选 |
| **D1** | 去掉责任分析块 | 同上 |
| **D2** | 去掉环境信息 | 同上 |
| **D3** | 去掉决策链 | 同上 |
| **D4** | 弱化结构化提示（仅 C 组后端生效） | 同上 |

**主实验建议**：A、B、C 均选 **D0**，在列表页各执行一次 **「批量跑 50 条并保存结果」**，得到三份 JSON。  
**消融实验建议**：固定 **C**，分别跑 **D0、D1、D2、D3、D4** 各一次，与 **C+D0** 对比。

**结果文件命名**：`cloud_experiment_results_{A|B|C}_{D0-D4}_yyyyMMdd_HHmmss.json`（应用外部存储目录，见说明文档 **§13.6**）。
