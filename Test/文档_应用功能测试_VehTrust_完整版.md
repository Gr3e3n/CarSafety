# 3.4 应用功能测试（VehTrust）

> **说明**：本章基于完整代码扫描（`app/src/main`, `backend/main.py`, `chaincode_and_API`, 数据库 schema）整理；与仓库现状对齐，图号与截图清单可按全文统一编号微调。

## 3.4.1 测试目的与范围

本部分对 **VehTrust（基于端侧智能分析与区块链可信存证的车载事故智证平台）** 的应用层功能进行验证，确保在 Android 端（含标准版与车机大屏适配版）及可选后端联调环境下，系统能够完成「**监控启动 → 事故采集与回放 → 责任与严重度分析 → AI 结构化研判 → 可信存证**」的闭环。

测试范围包括：

- **基本功能测试**：各 Activity 按设计完成数据采集、展示、分析与上链；前台服务正常运行；数据持久化有效。
- **可靠性测试**：异常输入、网络不可用、服务超时、批量实验降级等情况下系统是否稳定、提示是否明确、无崩溃。
- **可用性测试**：操作路径是否清晰、关键信息是否可读、车机场景下触控与字号是否满足设计标准（≥66dp 触控区）。

## 3.4.3 系统架构概览（代码层面）

### 四大核心 Activity

1. **MainActivity** (`MainActivity.kt`)  
   - 首页：模块卡片网格（6 个功能模块 + "事故溯源"特殊卡片）  
   - 启动 `AccidentMonitorService` 前台服务  
   - 模块卡片点击：特殊卡片"事故溯源" → `AccidentTraceActivity`；其他 → `ModuleDetailActivity`（只读参数）

2. **AccidentTraceActivity** (`AccidentTraceActivity.kt`)  
   - 事故事件列表（Room 中已存事件 + 新触发事件）  
   - 事件项点击 → `AccidentTraceDetailActivity`  
   - 底部按钮跳转 → `CloudExperimentActivity`（云端实验配置）  

3. **CloudExperimentActivity** (`CloudExperimentActivity.kt`)  
   - 实验组别选择：A（模板） / B（通用） / C（结构化，默认）  
   - 消融模式选择：D0（完整） / D1~D4（逐项消融）  
   - 配置持久化：SharedPreferences  
   - 批量 50 条实验按钮：读取 `assets/experiment_samples_realistic_50.json`，调用后端 `/api/accident/analyze/batch` 或逐条回退  

4. **AccidentTraceDetailActivity** (`AccidentTraceDetailActivity.kt`)  
   - ScrollView 纵向多区块展示：  
     - 事件概览卡片  
     - 事发位置地图（WebView）  
     - 可解释责任分析指标（反应时间/制动上升/峰值减速）  
     - 遥测回放（SeekBar + 曲线图）  
     - 深度学习分析结果  
     - 本地严重度推理（离线，不需网络）  
     - AI 事故分析（调用后端或回退）  
     - 区块链上链操作  

### 后端与 API

| 组件 | 文件 | 功能 | 超时 |
|------|------|------|------|
| **OpenAI 分析** | `OpenAiAnalysisApi.kt` | POST `/api/accident/analyze` + `/api/accident/analyze/batch` | 180s（覆盖 LLM + JSON 解析） |
| **区块链网关** | `BlockchainApi.kt` | POST `/upload`（上链），GET `/query`（查询）| 10s |
| **本地严重度** | `CollisionSeverityApi.kt` | 离线推理三分类 + 概率 + 关键因素 | - |
| **责任分析** | `ResponsibilityAnalyzer.kt` | 计算反应时间、制动上升、TTC、AEB 延迟等 | - |

### 数据库（Room）

四表架构（`db/AccidentEntities.kt`）：

| 表 | 含义 | 关键字段 |
|----|------|----------|
| `accident_events` | 事故事件主表 | id, type, timeMillis, severity, autoDrivingState, summary |
| `telemetry_points` | 遥测数据点（事故前后 20 秒） | eventId, tMs, speedKph, axMS2, brake, steerDeg, ... |
| `responsibility_results` | 责任分析结果 | eventId, driverFactor%, systemFactor%, environmentFactor%, reactionTimeMs, brakeRiseTimeMs, ... |
| `evidence_records` | 可信存证记录 | evidenceId, sha256, blockchainTxId, signature |

### 前台服务与监控

- **AccidentMonitorService** (`service/AccidentMonitorService.kt`)  
  - 前台服务（START_STICKY），保活 `AccidentMonitor` 采样循环  
  - 通知栏文案："事故溯源监控运行中 · 20Hz 高频采样 · 保留事故前后各 10 秒数据"  

- **AccidentMonitor** (`trace/AccidentMonitor.kt`)  
  - 环形缓冲：25 秒循环，20Hz 采样（每 50ms 一个点）  
  - 触发条件：加速度 ≤ -3.0 m/s�0�5 时冻结  
  - 事故窗口：事故前 10 秒 + 事故后 10 秒  
  - 冷却：触发后 10 分钟内不再触发

## 3.4.4 系统操作过程与界面说明

### （1）安全中心首页与前台服务（MainActivity）

**功能说明**：  
首页以网格展示 6 个安全模块卡片（驾驶辅助、疲劳监测、车道预警、碰撞预警、雨天安全、乘员安全）与"事故溯源"特殊卡片。应用启动时自动拉起 `AccidentMonitorService` 前台服务，在通知栏显示"事故溯源监控运行中"，表明 20Hz 采样与事故监听已激活。

**实际界面**：  
- 顶部：时间戳、日期、"监控运行中"绿色徽章  
- 中部标题："智能安全中心"  
- 下部网格：2 列模块卡片，其中"事故溯源"卡片宽度为 2 列  

**操作过程**：

1. 冷启动应用；  
2. 下拉通知栏，确认存在"事故溯源监控运行中"前台服务通知，文案包含"20Hz"与"事故前后各 10 秒"；  
3. 在首页浏览各模块卡片（状态由 `MockDataProvider` 定期更新，约 2 秒一次）；  
4. 短按非"事故溯源"模块卡片，进入 `ModuleDetailActivity`，核对参数与说明；  
5. 返回首页后，短按"事故溯源"卡片，进入 `AccidentTraceActivity`（列表）；  
6. 从列表返回首页（按 Back）。

**预期结果**：  
- 无崩溃；通知栏服务正常显示；列表与详情可互相导航；返回按钮功能正常。

### （2）事故溯源列表与云端实验配置（AccidentTraceActivity → CloudExperimentActivity）

**功能说明**：  
列表页展示 Room 中已持久化的事故事件及监控新触发的事件。顶部操作栏提供跳转至 `CloudExperimentActivity` 的按钮。在实验页，用户可选择**云端实验组别 A/B/C**（对应三种分析策略）与**消融模式 D0～D4**（渐进式去掉结构化输入块），配置写入 SharedPreferences，与《云端事故复盘能力实验说明文档》对齐。

**操作过程**：

1. 进入"事故溯源"列表页；  
2. 观察列表中已有的事故事件（若无，系统预生成 seedEvents 作演示数据）；  
3. 点击底部"云端实验配置"按钮进入 `CloudExperimentActivity`；  
4. 在实验页依次选择 A/B/C 与 D0～D4，观察单选框更新，返回列表；  
5. 再进实验页验证上次选择已保留（持久化验证）；  
6. 杀进程重启 App，进入实验页再次确认配置仍为上次选择。

7. **（可选）批量实验**：后端启动且 API Key 有效的前提下，点击 **"运行云端 50 条样本实验"**：  
   - 按钮变灰，显示"批量运行中…"  
   - 等待 30~120 秒（依后端 LLM 响应速度）  
   - 完成后界面显示输出 JSON 文件的绝对路径，格式为 `cloud_experiment_results_C_D0_20260523_120456Z.json`  
   - 可在 AS Device File Explorer 中验证文件存在与 JSON 格式正确

**预期结果**：  
- 列表与实验页可互相导航；选项可正常更改；配置重启后保留；批量任务结束后提示路径或清晰失败原因。

### （3）事故溯源详情页：回放、责任、严重度、AI、地图、上链（AccidentTraceDetailActivity）

**功能说明**：  
`AccidentTraceDetailActivity` 集成：
- **遥测回放**：事故前 10 秒 + 事故后 10 秒数据，通过 SeekBar 与播放按钮交互，实时展示曲线与仪表数据；  
- **责任分析指标**：由 `ResponsibilityAnalyzer` 计算的反应时间、制动上升时间、峰值减速等可解释指标，分三卡片展示；  
- **深度学习时序分析**：`DeepLearningAnalyzer` 生成的综合风险评分与模式识别结果（如"急制动"、"电子稳定性介入"等）；  
- **端侧严重度三分类**：`CollisionSeverityApi` 加载 `collision_severity_model.json` 离线推理，输出严重（Fatal）/ 中等（Serious）/ 轻微（Slight）三分类、置信度百分比、严重度指数（0~100）、概率分布表与关键因素；  
- **AI 事故原因分析**：调用后端 `/api/accident/analyze`，返回事故摘要、根因、综合分析、证据点、改进建议、模型说明；若失败或超时，自动回退本地规则；  
- **事故地点 WebView 地图**：使用 Leaflet + OSM 瓦片展示事故位置，支持"在外部地图应用中打开"；  
- **区块链上链**：调用 `BlockchainApi.uploadAccident()`，返回 Hash 与 TX ID；失败时提示错误并允许重试。

**实际界面**（ScrollView 纵向布局）：  
- 顶部：事件概览卡片（事故 ID、类型、时间、地点、触发原因）  
- Section 1：事发位置地图（WebView）  
- Section 2：可解释责任分析（三个指标卡片：反应时间/制动上升/峰值减速）  
- Section 3：遥测回放（SeekBar + 播放/重播按钮 + 曲线展示）  
- Section 4：深度学习结果  
- Section 5：本地严重度按钮与结果区（三分类 + 置信度 + 指数 + 概率表 + 关键因素）  
- Section 6：AI 分析按钮与结果区（摘要 + 根因 + 分析 + 证据 + 建议）  
- Section 7：上链按钮与结果区（成功 Hash 或失败提示）

**操作过程**：

1. 从列表点击一条事故进入详情页；

2. **回放验证**：  
   - 使用 SeekBar 拖动到事故前 5 秒位置，观察时间标签更新；  
   - 观察遥测曲线（速度/加速度/制动/方向盘）是否随 tMs 变化；  
   - 点击"播放"，观察 SeekBar 自动向后移动（实时播放）；  
   - 验证曲线平滑更新，无卡顿；  
   - 点击"暂停"，SeekBar 停止；点击"重新开始"回到事故前 10 秒；  

3. **责任指标验证**：  
   - 查看三个指标卡片，数值应为正整数或浮点数；  
   - 数值无 NaN 或无穷符号；  
   - 标签文案（如"反应延迟"/"制动充分"）与指标数值逻辑一致；  

4. **本地严重度推理**（断网场景推荐）：  
   - 点击"生成本地严重度研判"；  
   - 按钮变灰，显示"加载中…"；  
   - 完成后（通常 < 3 秒）展示：  
     - **预测结果**：如"严重碰撞" 或 "中等"  
     - **置信度**：如"87%"  
     - **严重度指数**：0~100 的数值  
     - **概率分布表**：三行对应 Fatal/Serious/Slight 的百分比  
     - **关键因素**：如"高速碰撞"、"制动无效"等  
     - **模型说明**：如"随机森林 v2.0（本地）"  

5. **AI 分析**（需后端）：  
   - 后端启动且 `OPENAI_API_KEY` 有效时，点击"生成 AI 事故分析"；  
   - 等待加载（通常 5~30 秒，慢模型 > 60s）；  
   - 完成后展示结构化字段：  
     - **事故摘要**：事故类型、时间、地点、触发原因的自然语言总结  
     - **根因判断**：系统输出的主要事故根源  
     - **综合分析**：多维度分析文本  
     - **证据点列表**：列举支撑判断的关键事实  
     - **改进建议**：驾驶员/系统/环境层面的防范措施  
     - **模型说明**：如"GPT-4o-mini（Cloud Group C D0）"  

6. **AI 回退（断网场景）**：  
   - 关闭后端或网络后再次点击 AI 分析；  
   - 应看到清晰提示（如"当前已回退到本地规则分析"）；  
   - 仍显示本地替代内容（如根据责任指标的模板化判断）；  
   - 不中断用户流程，不显示错误栈跟踪。

7. **地图验证**：  
   - 查看地图区是否加载成功（需网络访问 OSM 瓦片）；  
   - 若无网络，地图显示占位或白屏（可接受）；  
   - 点击"在外部地图应用中打开…"应唤起系统地图应用并展示事故地点。

8. **上链操作**：  
   - 网关正常情况：点击"上链"→ 加载 → 显示返回的 Hash（如 `0xabc123...`）+ 时间戳 + "已上链 �7�7" 状态；  
   - 网关关闭或 IP 错误：点击"上链" → 加载 → 显示红色错误文案（如"�7�4 上链失败：连接超时"）+ "重新上链"按钮；  
   - 验证按钮状态管理正确（成功后按钮禁用或变为"已上链"，失败后可重试）。

**预期结果**：  
- 回放平滑无卡顿；所有展示区字段完整；异常网络场景有清晰提示与合理回退；上链失败不导致崩溃。
